Quick start

Zero to code in under 5 minutes.

1

Install

Requires Go 1.21+ and the Claude Code CLI installed and configured.

{{ partial "code-block.html" (dict "code" "# install with go\ngo install github.com/jumppad-labs/spektacular@latest\n\n# or download a pre-built binary from the releases page\n# https://github.com/jumppad-labs/spektacular/releases") }}
2

Initialise your project

Run this from the root of your codebase. Creates a .spektacular/ directory with config, knowledge base, and template files.

{{ partial "code-block.html" (dict "code" "cd my-project\nspektacular init") }}
3

Create a spec

Scaffold a new spec file from the template, then fill in your requirements and constraints.

{{ partial "code-block.html" (dict "code" "spektacular new auth-feature --title \"User Authentication\"\n$EDITOR .spektacular/specs/auth-feature.md") }}
4

Generate a plan

The TUI launches, streams agent output in real time, asks clarifying questions, and writes the plan when done.

{{ partial "code-block.html" (dict "code" "spektacular plan .spektacular/specs/auth-feature.md") }}
5

Implement the plan

Hand the plan to a coding agent. Spektacular executes each task, then validates the result against your acceptance criteria.

{{ partial "code-block.html" (dict "code" "spektacular implement .spektacular/plans/auth-feature/plan.md") }}
{{/* ── Spec Format ───────────────────────────────────────── */}}

The spec format

Specs are plain markdown files. No special syntax — just structured sections that give the planning agent what it needs.

{{ partial "code-block.html" (dict "code" "# Feature: User Authentication\n\n## Overview\nAdd OAuth2 login with Google and GitHub\nproviders to the existing Express app.\n\n## Requirements\n- [ ] Users can sign in with Google OAuth2\n- [ ] Users can sign in with GitHub OAuth2\n- [ ] Session persists across browser refreshes\n- [ ] Logout clears session and redirects\n\n## Constraints\n- Must use existing Express backend\n- No new dependencies over 50KB gzipped\n- Cannot change the /api/users schema\n\n## Acceptance Criteria\n- [ ] Login redirects to provider, returns\n with valid session\n- [ ] Session cookie is httpOnly, secure,\n sameSite=strict\n- [ ] Logout flow works end-to-end\n\n## Technical Approach\nUse passport.js for OAuth2 strategy.\nIntegrate with existing session middleware.\n\n## Success Metrics\n- OAuth2 login completes in under 2 seconds\n- Zero increase in /api/users error rate\n\n## Non-Goals\nSocial login with Apple or Microsoft.") }}
{{- range (slice (dict "section" "## Overview" "body" "A concise 2–3 sentence summary answering: what is being built, what problem does it solve, and who benefits? Grounds the agent before it reads anything else.") (dict "section" "## Requirements" "body" "A checklist of discrete behaviours. Use active voice (\"Users can…\"). Each item should be independently verifiable and focus on what, not how.") (dict "section" "## Constraints" "body" "Non-negotiable boundaries — existing APIs, dependency limits, performance budgets. Violations are plan failures. Leave blank if none.") (dict "section" "## Acceptance Criteria" "body" "Binary pass/fail conditions, each traceable to a requirement and testable by someone who didn't write the code. These become the verification steps in the output plan.") (dict "section" "## Technical Approach" "body" "High-level technical direction — key architectural decisions, preferred patterns, integration points, and known risks. Leave blank to let the planner propose an approach.") (dict "section" "## Success Metrics" "body" "How you'll know it works well after delivery. Quantitative (\"p99 latency < 200ms\") or behavioural (\"users complete the flow without support\"). Leave blank if not applicable.") (dict "section" "## Non-Goals" "body" "Explicitly out of scope — prevents scope creep and over-engineering. Leave blank if there are no exclusions to call out.") ) }}

The pipeline

Three stages: write the spec, generate a plan scaled to complexity, then implement and validate.

Run spektacular new to scaffold a spec from the template, then fill in your requirements, constraints, and acceptance criteria. The spec is plain markdown — no special syntax, just structured sections.

Analyse uses a cheap, fast model to score the spec on a 0.0–1.0 complexity scale — examining requirement count, constraint density, technical keywords, and spec length. The score is returned in under a second.

Plan uses that score to select a model tier. It loads your project knowledge base, explores the codebase, and runs interactively in the TUI — streaming markdown output and surfacing clarifying questions you answer by pressing a key. The result is written to .spektacular/plans/.

Implement hands the plan to a coding agent as a subprocess. The agent executes each task from the plan, and a validation step verifies the output against your acceptance criteria — so you know the implementation matches the spec.

{{/* ── Configuration ─────────────────────────────────────── */}}

Configuration

Model routing and complexity thresholds are controlled by .spektacular/config.yaml.

{{ partial "code-block.html" (dict "code" "models:\n default: anthropic/claude-3-5-sonnet-20241022\n tiers:\n simple: anthropic/claude-3-5-haiku-20241022 # score 0.0–0.3\n medium: anthropic/claude-3-5-sonnet-20241022 # score 0.3–0.6\n complex: anthropic/claude-3-opus-20240229 # score 0.6+\n\ncomplexity:\n thresholds:\n simple: 0.3\n medium: 0.6\n complex: 0.8") }}

Model selection is automatic. Raise or lower the thresholds to tune how aggressively Spektacular routes to more capable (and more expensive) models. Environment variables are expanded — set ANTHROPIC_API_KEY and the default agent will use it automatically.
